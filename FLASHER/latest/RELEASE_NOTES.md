# OPF-FLASHER latest (Linux 0.0.2+VC95, Windows 0.0.2+VC107)

`FLASHER/latest` is a mixed package. The Linux deb is still the tagged v0.0.3 build. The Windows portable exe is a newer desktop build. The immutable folder `FLASHER/v0.0.3` and the git tag `v0.0.3` on `opelpanfan/OPF-FLASHER` are unchanged (both platforms there remain 0.0.2+VC95 from `6a925e2494777bb4e1a40eb6c3d8f2790873a812`).

- **Linux:** `OPF-FLASHER-linux-amd64.deb` — amd64 package 0.0.2+VC95, built on the OptiPlex from `opelpanfan/OPF-FLASHER` commit `6a925e2494777bb4e1a40eb6c3d8f2790873a812` on `master-grok` (git tag `v0.0.3`). Bundled Qt 6.8.3, esptool, and OpenOCD. Install with your package manager (`dpkg -i` or equivalent). Needs common system graphics and font libraries listed in the package Depends.
- **Windows:** `OPF-FLASHER-win-x64-VC107.exe` (the build number is in the file name; `OPF-FLASHER-win-x64.exe` is a copy of the newest build so old links keep working) — portable 7-Zip LZMA2 self-extractor, app version 0.0.2+VC107 from `opelpanfan/OPF-FLASHER` commit `2becc6d778ee696d9d198960c7aebefe3d676853` on `master-grok`. Cross-built on the OptiPlex (Qt 6.8.3, official MSVC kit, clang-cl). This Windows build has not been tested on a real Windows machine. Run the exe, extract the `OPF-FLASHER-qt-win64` folder, and start `OPF-FLASHER.exe` from that folder. Leave the Qt DLLs, the MSVC runtime, plugin folders (`tls/` included), and `tools/` next to the exe. esptool 5.5.0 and xPack OpenOCD 0.12.0-7 are bundled as Windows binaries. The package includes `tls/qschannelbackend.dll` and `tls/qcertonlybackend.dll`, which are required for HTTPS (the firmware feed index and downloads). MQTT in this app does not use TLS.

macOS is not included.

What changed in the Windows package since the v0.0.3 (VC95) feed build:

- TLS plugin folder is packaged and checked, and the app logs whether HTTPS will work at startup. A crash on Windows writes a minidump next to the session log.
- esptool 5 no longer starts a second verify run on the same COM port after a hard reset (ESP32-S3 native USB can get a new COM number). Serial errors use Windows wording (no "dialout") and mention CH340, CP210x, and ESP32-S3 drivers.
- CAN help names the vendor driver each backend needs on Windows, uses the Qt PEAK names (`usb1`, not `PCAN_USBBUS1`), and says listen-only still ACKs on vendor adapters. gs_usb / candleLight users are pointed at slcan firmware or a PCAN adapter.
- BLE pairing on Windows: the app pairs each device itself before any GATT access (WinRT custom pairing with ProvidePin / ConfirmPinMatch / ConfirmOnly / DisplayPin, protection level EncryptionAndAuthentication; works with LE Secure Connections and legacy pairing). It answers the PIN request with 123456 or the PIN you type in the app's own prompt, pairs several slaves one after another, removes a stale Windows bond and pairs again once, and if Windows reports a pairing already in progress for the device it unpairs, waits and retries once, then tells you to close the Settings dialog / remove the device / toggle Bluetooth. A link the device drops right after connecting is reported as a failed connect, not as Ready. The "already connected on this computer" check is skipped on Windows. BLE OTA logs the MTU and uses acknowledged writes when Windows reports 23 or does not report one.
- Forget: Nearby devices that are paired show a Forget button (in the slot where Setup was; Setup is on the Connected card). It removes the Bluetooth pairing (Windows `UnpairAsync`, Linux BlueZ `RemoveDevice`) and the remembered-paired entry. The next Connect pairs again.
- BMS Setup (VC106-107): every picker writes the firmware id (item data), never the list position; options a board, role or firmware cannot take stay in the list disabled. A slave (role Slave) shows and writes only what it needs: Slave ID 1-15 always (the save asks for confirmation when another connected slave has the same id), Type, battery type and cell rows; it has no display CAN, inverter CAN, dash CAN commands/IDs, contactor control or contactor GPIO rows and never writes them (fixes 'Read-back did not match' for display CAN on a slave). Slave COM is master-only (a slave shows the raw value read-only). Contactor control defaults to GPIO for every battery type. Failsafe voltage is checked against the chemistry window and must be 0 for battery type NONE. Board 7 None is listed; Display CAN Off is never changed automatically; failsafe/cell voltage/current fields are whole numbers; write order is role, slave id, slave count, Slave COM with one reboot note after the set; BLE OTA logs the image sha256.

Linux is unchanged from the v0.0.3 (VC95) package.
